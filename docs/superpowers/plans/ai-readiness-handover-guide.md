# מדריך המשכיות והעברת מקל: הכנת `feat/ai-intake` למיזוג ל-`main`
*(Ten10 AI Multichannel — Handover & Readiness Guide)*

> **למי מיועד המסמך:** לכל סוכן AI / פלטפורמה / מפתח שממשיך את תהליך הביקורת והמיזוג של ענף ה-AI ל-`main`. קרא מסמך זה תחילה — הוא מרכז את כללי הברזל, שיטת העבודה, תמונת המצב המדויקת והצעד הבא.

---

## 1. רקע ומטרת העל

- **הפרויקט:** Ten10 — מערכת ניהול מעשרות ופיננסים אישיים (React 19 + TypeScript + Vite + Tailwind + Supabase PostgreSQL + Edge Functions ב-Deno + Tauri/Android).
- **הענף הנבדק:** `feat/ai-intake`.
  נצברו בו מעל 660 קומיטים ו-600 קבצים (כ-34,000 שורות קוד חדשות). הוא מכיל מערכת רב-ערוצית לקליטת תנועות (טקסט חופשי, קבלות בתמונה/PDF, הקלטות קול, שאלות נתונים פיננסיות ודפי הלכה).
- **העיקרון המנחה (`.cursor/rules/ai-multichannel/RULE.md`):**
  *"המודל קורא בעיפרון, Ten10 רושם בעט"*. המודל רק מציע טיוטה או מסווג, הקוד הדטרמיניסטי מחשב ומאמת, והמשתמש מאשר. רישום ל-`public.transactions` מתבצע **אך ורק** דרך הפונקציה המאובטחת `ai.commit_intake_items`.
- **כלל ברזל עליון:**
  **עד לסיום גל 6, לעולם לא פותחים PR ולא דוחפים (`git push`) ישירות ל-`main`!**
  כל העבודה התבצעה כ-PRs ממוקדים אל תוך `feat/ai-intake`. המיזוג הסופי ל-`main` יבוצע אך ורק בסיום גל 6 כשהכל נבדק ומאחורי Feature Flags כבויים.

## 2. שיטת העבודה: שני תפקידים (Orchestrator vs Worker)

כדי להימנע מהטיות, שכחה ועומס הקשר (על פי פרקטיקות Anthropic ו-Stripe):
1. **סשן המאמת / שומר הסף (Gatekeeper / Orchestrator):**
   - מנהל את תוכנית העבודה הכוללת.
   - מקבל החלטות מוצר ואדריכלות.
   - בודק בעין ביקורתית את ה-Diff של כל תיקון.
   - ממזג PRs לתוך `feat/ai-intake` ומנפיק את הפרומפט לגל הבא.
2. **סשן הביצוע (Worker Session — בהקשר נקי `Fresh Context`):**
   - מקבל פרומפט מוגדר היטב לגל ספציפי.
   - מריץ בדיקות, משגר סאב-אייג'נטים מתמחים לקריאה בלבד (`research`).
   - מבצע אך ורק תיקונים מוסכמים ומאושרים.
   - מריץ את כל שערי האיכות הדטרמיניסטיים, עושה commit מקומי, ועוצר בלי לדחוף עד לאישור ה-Gatekeeper.

## 3. שערי האיכות הדטרמיניסטיים (חובה להריץ לפני כל אישור)

בכל שינוי קוד, כל 5 השערים חייבים להיות ירוקים ב-100%:
1. `npm run typecheck` (חייב להסתיים ב-`0` שגיאות חדשות מעל ה-baseline).
2. `npm run lint:ratchet` (חייב להסתיים ב-`0` אזהרות/שגיאות מעל ה-baseline).
3. `npm run check-supabase-imports` (מוודא שכל ייבואי Supabase ב-Edge נעולים לגרסה המאושרת).
4. `npm run test:infra` (בדיקות משמר של ארכיטקטורה, תאימות Deno, ואיסור זליגת Tauri ל-Web).
5. `npm test` (סוויטת Vitest המלאה — כ-185 קבצים, מעל 1,300 טסטים).

### סטטוס מפורט:
- ✅ **גל 0 (הקפאת ענף ושערים דטרמיניסטיים):** הושלם. חסם פריסת הפרודקשן של ה-Edge Functions (`P0-1`) ננעל בטסט AST חדש. קובצי בדיקות C4 לא-מעוקבים גובו ל-`test-results/c4-untracked-backup/`.
- ✅ **גל 1 (קוד מת, כפילויות ויישור ארכיטקטורה):** הושלם ומוזג ב-**PR #647**. נמחקו קבצים יתומים, אוחדו חוזים משותפים, ותוקנו לוגי שגיאות ב-Edge.
- ✅ **גל 2 (התאמה למוצר, דומיין Ten10 ויוז-קייסים חסרים):** הושלם ומוזג ב-**PR #648**. חומש אוטומטי (`W2-M1`), 12 מטבעות (`W2-M2`), נמען בתרומות + SQL fallback (`W2-M3`), פסיק אלפים בטוח (`W2-M4`), רשימות מפוצלות והוראות קבע (`W2-P1..P6`).
- ✅ **גל 3 (דיוק מודלי AI, מיטוב תהליך ו-Evals):** הושלם ומוזג ב-**PR #649**. שער C7 עבר בשתי ריצות מלאות: `wrong_save = 0`, `dead_end` צומצם ל-3 (ירידה של 75%), כוונות 99/99 (100%), חיסכון של כ-35k טוקנים בכל ריצה, ועלות שיחה מלאה נחתכה ב-50% (~$0.12).
- ✅ **גל 4 (אבטחה, ציד באגים, DB ועמידה בסקייל):** הושלם ומוזג ב-**PR #650** + תיקון חתימה ב-**PR #651**. מיגרציה `20261102180000` (אינדקס `usage_events`, אילוץ `question_period`, סגירת 16 RPCs ל-`authenticated`), שחרור מכסות ב-`catch`, ופריסת 8 פונקציות ה-Edge ל-testing.
- ✅ **גל 5 (ממשק משתמש: רספונסיביות, שפות עברית/אנגלית, RTL/LTR ו-Themes):** הושלם ומוזג ב-**PR #652**. סימטריית תרגום 100%, 33 בדיקות RTL לוגיות קבועות ב-`test:infra`, רספונסיביות מובייל (`dvh`, מקלדת וירטואלית, גלילה וריפוד safe-area), והקשחת Safe-by-default של `trial-users.ts` (פתיחה רק עם `AI_TRIAL_ONLY=false` מפורש).
- 🔵 **גל 6 (תיעוד, רצף מיגרציות, Kill Switch ומיזוג סופי ל-`main`):** **הצעד הבא! (ראו פרק 5)**.

## 5. הצעד הבא: הנחיות לביצוע גל 6 (Migrations Sequence, Kill Switch & Main Rollout)

בגל 6 מבצעים את שלב הסיום של תוכנית ההכשרה לקראת מיזוג הענף ל-`main`:

### משימות הליבה של גל 6:
1. **תיארוך מחדש של 15 המיגרציות הישנות (`B-1`):**
   - ב-`main`, המיגרציה האחרונה היא `20261019195400_tithe_balance_as_of.sql`.
   - ב-`feat/ai-intake`, יש 15 מיגרציות בעלות timestamp קודם (`20261019020000` עד `20261019170000`).
   - יש לתארך אותן מחדש כך שיופיעו כרונולוגית אחרי `20261019195400`, למניעת כשל בריצת `supabase db push` בייצור.
   - יש לעדכן בדיקות תשתית המצטטות שמות אלו (כגון `receipt-artifact-allowlist.test.ts`, `supabase-deploy-order.test.ts`).
2. **אימות קובצי Rollback ושלמות מסד הנתונים:**
   - בדיקה שקובצי ה-rollback קיימים ומכסים את המיגרציות.
3. **בדיקת Kill Switch מוחלטת (Flag-Off Audit):**
   - וידוא שבהיעדר הדגל (`VITE_AI_INTAKE_ENABLED !== "true"` או כבוי), שום כפתור, מגירה או קריאת רשת של ה-AI אינם נחשפים למשתמשי ייצור.
4. **שערי איכות דטרמיניסטיים:**
   - הרצת `npm run typecheck`, `npm run lint:ratchet`, `npm run check-supabase-imports`, `npm run test:infra`, `npm test`.
5. **צ'קליסט פריסה שקטה ומיזוג ל-`main`:**
   - תזמון מחוץ לשעות ה-Cron של `process-recurring-transactions` (`00:00, 07:00, 18:00, 19:00 UTC`).
   - הכנת ה-PR הסופי מ-`feat/ai-intake` אל `main`!
