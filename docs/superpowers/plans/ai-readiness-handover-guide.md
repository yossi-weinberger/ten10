*(Ten10 AI Multichannel — Handover & Readiness Guide)*

> **למי מיועד המסמך:** לכל סוכן AI / פלטפורמה / מפתח שממשיך את תהליך הביקורת והמיזוג של ענף ה-AI ל-`main`. קרא מסמך זה תחילה — הוא מרכז את כללי הברזל, שיטת העבודה, תמונת המצב המדויקת והצעד הבא.

## 1. רקע ומטרת העל

- **הפרויקט:** Ten10 — מערכת ניהול מעשרות ופיננסים אישיים (React 19 + TypeScript + Vite + Tailwind + Supabase PostgreSQL + Edge Functions ב-Deno + Tauri/Android).
- **הענף הנבדק:** `feat/ai-intake`.
  נצברו בו מעל 660 קומיטים ו-600 קבצים (כ-34,000 שורות קוד חדשות). הוא מכיל מערכת רב-ערוצית לקליטת תנועות (טקסט חופשי, קבלות בתמונה/PDF, הקלטות קול, שאלות נתונים פיננסיות ודפי הלכה).
- **העיקרון המנחה (`.cursor/rules/ai-multichannel/RULE.md`):**
  *"המודל קורא בעיפרון, Ten10 רושם בעט"*. המודל רק מציע טיוטה או מסווג, הקוד הדטרמיניסטי מחשב ומאמת, והמשתמש מאשר. רישום ל-`public.transactions` מתבצע **אך ורק** דרך הפונקציה המאובטחת `ai.commit_intake_items`.
- **כלל ברזל עליון:**
  **לעולם לא פותחים PR ולא דוחפים (`git push`) ישירות ל-`main`!**
  כל העבודה מתבצעת כ-PRs ממוקדים אל תוך `feat/ai-intake`. המיזוג הסופי ל-`main` יבוצע רק בסוף גל 6 כשהכל נבדק ומאחורי Feature Flags כבויים.

## 2. שיטת העבודה: שני תפקידים (Orchestrator vs Worker)

כדי להימנע מהטיות, שכחה ועומס הקשר (על פי פרקטיקות Anthropic ו-Stripe):
1. **סשן המאמת / שומר הסף (Gatekeeper / Orchestrator):**
   - מנהל את תוכנית העבודה הכוללת.
   - מקבל החלטות מוצר ואדריכלות.
   - בודק בעין ביקורתית את ה-Diff של כל תיקון.
   - ממזג PRs לתוך `feat/ai-intake` ומנפיק את הפרומפט לגל הבא.
2. **סשן הביצוע (Worker Session — בהקשר נקי `Fresh Context`):**
   - מקבל פרומפט מוגדר היטב לגל ספציפי.
   - מריץ בדיקות, משגר סאב-אייג'נטים מתמחים לקריאה בלבד (`research`).
   - מבצע אך ורק תיקונים מוסכמים ומאושרים.
   - מריץ את כל שערי האיכות הדטרמיניסטיים, עושה commit מקומי, ועוצר בלי לדחוף עד לאישור ה-Gatekeeper.

## 3. שערי האיכות הדטרמיניסטיים (חובה להריץ לפני כל אישור)

בכל שינוי קוד, כל 5 השערים חייבים להיות ירוקים ב-100%:
1. `npm run typecheck` (חייב להסתיים ב-`0` שגיאות חדשות מעל ה-baseline).
2. `npm run lint:ratchet` (חייב להסתיים ב-`0` אזהרות/שגיאות מעל ה-baseline).
3. `npm run check-supabase-imports` (מוודא שכל ייבואי Supabase ב-Edge נעולים לגרסה המאושרת).
4. `npm run test:infra` (בדיקות משמר של ארכיטקטורה, תאימות Deno, ואיסור זליגת Tauri ל-Web).
5. `npm test` (סוויטת Vitest המלאה — כ-185 קבצים, מעל 1,300 טסטים).
